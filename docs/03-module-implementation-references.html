2用 CF 原生 vs 从 hermes 移植

🟢 直接用 CF 原生（薄装配层即可）

  • 技能 — agents/skills
  • 上下文 — Sessions + createCompactFunction
  • 调度 — this.schedule
  • 子 agent — subAgent() / runAgentTool()
  • MCP — addMcpServer / McpAgent
  • 模型容错 — AI Gateway Universal Endpoint
  • 存储 — R2 · 可观测 — diagnostics + Tail Worker + AI Gateway

🔧 需从 hermes 移植算法（CF 没做）

  • loop guardrails — tool_guardrails.py 断路器
  • session_search + MEMORY/USER — 冻结快照
  • 学习闭环 — background_review.py 4层偏好 + curator.py 伞形
  • toolsets 分发 + check-fn
  • 连接器注册表 — platform_registry.py 工厂
  • 凭证轮换 — credential_pool.py

📋 借 pi 样板：providers/cloudflare.ts（AI Gateway 接入）· Usage.cost（成本结构）· before/afterToolCall hook 形态

3第一段代码建议

最小、独立、CF 原生 + 一点 hermes 算法 —— session_search（记忆引擎地基）。

  1. 建表（CF 原生 this.sql）在 DO 里建 messages + messages_fts USING fts5(content) + insert/delete/update trigger；中文场景加 messages_fts_trigram (tokenize='trigram')。D1 已确认支持 fts5。
  2. session_search 工具（hermes 算法）三模式单形状：DISCOVERY（MATCH+snippet()+bm25 rank+anchored 窗口）/ SCROLL（按 id 取窗口）/ BROWSE（按时间）。全程纯 SQL，零 LLM。
  3. CJK 路由≥3 中文字走 trigram 表，1-2 字 LIKE 兜底（照 hermes_state.py:2819）。
  4. 验证单测：插入若干消息 → DISCOVERY 命中高亮 + 窗口 → SCROLL 翻页 → BROWSE 列最近。独立可测，不依赖模型。
为什么先它：独立、零 LLM、可单测，且即体现「完整 agent」差异 —— 跨会话召回连 Claude Managed Agents 都没暴露这个原语。
